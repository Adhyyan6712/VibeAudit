SQL injection risk in login query

Critical Confirmed OWASP A03 Injection
Evidence · app.py
Why it matters
User input is placed directly into the query text. Someone could change what the query does and read or alter data they should not reach, such as other users’ accounts.
How the severity was set
Severity 5 × confidence high (1.0) = risk 5.0 → Critical
Suggested fix
BEFORE
q = "SELECT * FROM users WHERE name='" + name + "'"
AFTER
db.execute("SELECT * FROM users WHERE name = ?", (name,))
STEPS
    ⚠️ Human review recommended. AI suggestions can be wrong. Check the fix before applying it.

    How is this scored?

    VibeAudit evaluates risk deterministically so results are explainable, objective, and reproducible.

    Risk = Severity (1–5) × Confidence (0.4 | 0.7 | 1.0)
    Penalty per finding = Risk × 3
    Needs-validation findings count at 50% penalty.
    Rejected findings count at 0% penalty.
    Security score = max(0, 100 - sum of penalties)
    Risk bands:
    • Critical: Risk ≥ 4.0
    • High: Risk ≥ 3.0
    • Medium: Risk ≥ 2.0
    • Low: Risk < 2.0

    Verdict and scoring inspired by Cloudflare's open-source security-audit-skill (MIT).
